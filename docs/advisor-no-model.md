# Прогон без Qwen

Это промпт для агента-тестера. Цель — дойти до заявки в кабинете, когда контейнер `qwen` не запущен и бэкенд его не вызывает. Формула ведёт анкету сама. Голос на каждом шаге анкеты — `formula`, не `qwen`.

## Поднять стенд

Из корня репозитория. Не делать `docker compose down -v`. Не удалять заявки и кредиты.

```sh
docker compose stop qwen
docker compose -f docker-compose.yml -f docker-compose.no-model.yml up -d --build
```

`stop` гасит только модель. База, Redis и том с весами остаются. Вторая команда поднимает базу, Redis, бэкенд и сайт. Сервиса `qwen` в этом запуске нет: у бэкенда пустой `ADVISOR_LLM_URL`, он не ждёт модель.

Проверить перед чатом:

- `docker compose ps` не показывает работающий `qwen`. Контейнер либо отсутствует, либо остановлен.
- http://localhost:8000/health отвечает `200` и `{"status":"ok"}`.
- Сайт http://localhost:8080 открывается.

Если кто-то потом выполнит обычный `docker compose up` без второго файла, модель снова войдёт в стенд. Для этого прогона так не делать.

## Что уже считается

Юнит-тесты формулы не ходят в модель:

```sh
docker compose -f docker-compose.yml -f docker-compose.no-model.yml run --rm --no-deps -v "$PWD/backend:/srv" backend python -m unittest discover -s tests -p 'test_*.py'
```

Ожидание: все тесты OK.

## Целевое действие

Человек без модели доходит от «Попробовать продукт» до заявки в кабинете. Один раз, на номере `79001000002` (Илья Морозов). СМС не уходит, код в чате — `0000`. После кода есть кнопка в кабинет, в кабинете видна новая заявка на оборудование. Старые заявки не удалять. Новую тоже не удалять.

Ширина окна около 1280. На `/` сверху «Попробовать продукт», снизу регистрация. Списка продуктов на этой странице нет.

Каждый ход в `POST /api/advisor` смотреть `voice` и `answers`. На шагах анкеты `voice` равен `formula`. Если где-то `qwen` — модель всё ещё отвечает, это провал прогона.

| Шаг | Что сделать | Ожидание |
| --- | --- | --- |
| 1 | «нужен станок для цеха» | цель `equipment`, эта же фраза уже записана как цель заявки. Ответ просит сумму 500 000–5 000 000 ₽ и ставку 16% |
| 2 | «какая ставка на оборудование?» | «Вопрос не понят. Попробуйте переформулировать.» Сумма и цель не сдвигаются. Новой ставки нет |
| 3 | «2 000 000» | сумма 2 000 000, дальше срок 12–60 месяцев |
| 4 | «24» | срок 24 месяца, дальше выручка. Отдельного вопроса «какая цель» нет: она взята из первой реплики |
| 5 | «станок для цеха» ещё раз | сумма и цель не меняются, снова просит выручку |
| 6 | «180000» | выручка записана, дальше номер |
| 7 | «Круто давай оформлять что от меня требуется?» | следующий шаг анкеты, не отказ «в карточках этого нет». Ответ начинается с «Оформляем.» |
| 8 | `79009999999` | `401`, «Номер не найден.», пользователь не создаётся, номер в ответах пустой |
| 9 | `79001000002` | номер записан, в ответе есть код `0000`, токена ещё нет |
| 10 | `0000` | `done: true`, заявка на этом номере, есть переход в кабинет |

В кабинете Ильи новая заявка: кредит на оборудование, 2 000 000 ₽, срок 24 месяца. В цели заявки лежит первая фраза, «нужен станок для цеха», а не повтор. Решение может быть одобрением, уменьшением или отказом — его посчитать и записать. Заявку не удалять.

Неизвестный номер и код `0000` проверять и в чате на сайте, не только прямым POST. На шаге 2 прямой POST и чат должны совпасть: оба просят переформулировать, оба не меняют сумму.
