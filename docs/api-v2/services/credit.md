# credit

Сервис `backend`. База только своя, хост Compose — `credit-db`.

Кабинет, сессия, заявки и кредиты описаны в `docs/contract.md`. Клиент вызывает те же пути через `@alfa-hack/core-api`.

Вход только по номерам из `GET /api/demo-profiles`. Эти пользователи и их кредиты создаются при старте сервиса. Неизвестный номер не регистрируется.

`POST /api/advisor` подбирает продукт до входа. Формула решает вопрос, вилку и когда спросить номер. Голос — сервис `qwen` в Compose: та же базовая Qwen2.5-1.5B-Instruct без адаптера, квант Q4 на CPU, адрес `ADVISOR_LLM_URL` (`http://qwen:8766/paraphrase`). Ответ нужен в том же ходе, поэтому вызов синхронный. Иначе фразу собирает шаблон по триггерным словам. Свободный вопрос ищется по `ML/knowledge` и пересказывается только из найденной карточки. Ссылка на уже сказанное («этот кредит», «что ещё») ищется по последним репликам человека и последнему ответу чата. Модель видит до шести реплик. Просьба оформить заявку возвращает к следующему шагу анкеты. Без карточки модель отказывает своими словами и не выдумывает ответ. Без модели чат просит переформулировать. Неизвестный номер в реплике даёт `401` и «Номер не найден.», пользователь не создаётся. Код `0000` записывает заявку на демо-номер и открывает сессию. Подробности в `docs/contract.md`.

## `GET /health`

Токен не нужен. Это readiness, не часть кабинетного JSON.

`200`

```json
{"status": "ok"}
```

`503` — Postgres не ответил на `SELECT 1`.

```json
{"status": "error", "reason": "db"}
```

Путь смотрят у процесса сервиса. На стенде это порт 8000. Origin кабинета на `/health` отдаёт HTML страницы входа со статусом 200. Это не готовность и не кабинетный JSON.

## Кэш

`GET /api/products` и `GET /api/products/{code}` могут прийти из Redis. Форма ответа та же, что в контракте.
