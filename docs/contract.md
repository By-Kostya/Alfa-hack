# Контракт анкеты

Фронт и бэк говорят через один запрос. Фронт не выбирает пайплайн. Бэк сначала считает лимит нейросетями. Если этот шаг не собрался, тот же запрос считает лимит формулой. Ответ в обоих случаях одной формы.

Номер телефона сохраняется в заявке. СМС и почта наружу не уходят: подтверждение — это ввод номера на экране.

## Экраны

Порядок как на схеме.

1. Точка входа ведёт в личный кабинет или сразу в продукт по ссылке.
2. Личный кабинет даёт два продукта: `working_capital` (оборотный кредит) и `startup` (кредит на старт).
3. Оборотный кредит собирает числа. Кредит на старт собирает бизнес-план. Сумма и срок есть у обоих.
4. Экран «Заполняет анкету» отправляет один `POST /api/applications`.
5. Экран подтверждения просит номер телефона и повторяет тот же запрос с заполненным `phone`, либо телефон уже в первом запросе.
6. Ответ показывается в кабинете: лимит, платёж, какой пайплайн сработал.

Фронт рисует `pipeline` из ответа и не переключает его сам.

## Запрос

`POST /api/applications`

`Content-Type: application/json`

```json
{
  "product": "working_capital",
  "loan_amount_rub": 800000,
  "loan_term_months": 12,
  "phone": "79001234567",
  "purpose": "пополнение оборота",
  "profitability_rub": 160000,
  "profitability_confirmed": true,
  "collateral": false,
  "business_plan": "",
  "own_funds_rub": 100000,
  "credit_rating": 500
}
```

| Поле | Тип | Кто заполняет |
| --- | --- | --- |
| `product` | `working_capital` или `startup` | оба продукта |
| `loan_amount_rub` | целое, больше 0 | оба |
| `loan_term_months` | целое, от 1 до 360 | оба |
| `phone` | строка из цифр, 10–15 знаков | оба, на подтверждении |
| `purpose` | строка | оборотный, со схемы «цель» |
| `profitability_rub` | целое, руб/мес, может быть отрицательным | оборотный, со схемы «доходность» |
| `profitability_confirmed` | bool | оборотный |
| `collateral` | bool | оборотный, «есть ли залог» |
| `business_plan` | строка | старт, со схемы «бизнес план» |
| `own_funds_rub` | целое или `null` | оба, если человек указал свои деньги |
| `credit_rating` | целое 0–1000 или `null` | оба, если рейтинг уже известен |

Для `working_capital` обязательны сумма, срок, цель, доходность и флаг подтверждения. `business_plan` может быть пустым.

Для `startup` обязательны сумма, срок и непустой `business_plan`. Доходность с формы не требуется: её достаёт энкодер из текста.

`collateral` бэк принимает и сохраняет. Текущий лимит от залога не меняется.

## Ответ

`200` — заявка посчитана, любым пайплайном.

```json
{
  "id": "app-1",
  "pipeline": "ai",
  "fallback": false,
  "product": "startup",
  "loan_amount_rub": 800000,
  "loan_term_months": 12,
  "monthly_payment_rub": 74108,
  "flow_rub": 160000,
  "limit_rub": 800000,
  "decision": "approve",
  "report": {
    "flow_basis": "explicit",
    "risks": ["client_concentration", "lumpy_revenue"],
    "quote": "Средний поток равен 160000 руб. в месяц."
  }
}
```

`pipeline` — `ai` или `math`. `fallback: true` только у математики, когда нейросеть не ответила.

`decision`:

- `approve` — `limit_rub` равен запрошенной сумме
- `reduced` — `limit_rub` больше 0 и меньше суммы
- `reject` — `limit_rub` равен 0
- `unknown` — потока нет, лимит не ставится, `limit_rub` равен `null`

`report` при `pipeline: math` приходит с пустыми `risks` и `quote`, `flow_basis` равен `form`, если поток взят из `profitability_rub`.

`400` — в теле нет обязательного поля. Форма:

```json
{"error": "Для кредита на старт нужен бизнес-план."}
```

## Какой пайплайн считает

Один и тот же URL.

**AI, по умолчанию.**

1. Если продукт `startup` или в запросе есть текст плана, энкодер читает `business_plan` и возвращает поток, основание, риски и цитату. Платёж и покрытие из текста модели выбрасываются.
2. Если плана нет, поток — это `profitability_rub` с формы.
3. Платёж считает формула аннуитета: ставка 20% годовых, сумма и срок из запроса.
4. Скорер лимита получает поток, платёж, сумму, срок, свои деньги, рейтинг, флаг подтверждения доходности и риски. На выходе класс: `0`, `300000`, `800000` или `2000000`. Класс выше запрошенной суммы обрезается до суммы.

**Математика, фолбек.** Включается, если энкодер не вернул JSON, цитаты нет в тексте плана, или скорер не загрузился.

1. Поток берётся из уже полученного отчёта энкодера, если он успел посчитаться. Иначе из `profitability_rub`.
2. Платёж — тот же аннуитет.
3. Лимит — наибольшая ступень `300000`, `800000`, `2000000`, которая не выше запроса и чей аннуитет не больше потока. Если поток не положительный, лимит `0`. Если потока нет вообще, `decision` равен `unknown`.
4. Риски в этом ответе пустые.

Фронт при `fallback: true` показывает лимит так же, как при AI, и подписывает, что сработала формула.
