# Контракт личного кабинета

Фронт и бэк говорят JSON. Базовый префикс `/api`. Авторизация — заголовок `Authorization: Bearer <token>`. Токен выдаёт вход по номеру телефона.

Подтверждение заявки — это ввод номера в форме. Номер сохраняется в кабинете. Шлюза СМС и почты нет.

Пайплайн лимита один URL. Бэк сначала считает нейросетями (`pipeline: ai`). Если этот шаг не собрался, тот же запрос считает формулой (`pipeline: math`). Фронт пайплайн не выбирает и рисует поле из ответа.

Ошибки везде одной формы. Тело, которое не разбирается как JSON, тоже `400`: в `error` человеческий текст, не сообщение парсера.

```json
{"error": "Текст для человека."}
```

| Код | Когда |
| --- | --- |
| `400` | Тело не сходится с правилами поля |
| `401` | Нет токена или токен чужой |
| `404` | Заявки или кредита нет среди своих |

Чужие заявки и кредиты для этого токена выглядят как `404`.

Телефон — строка из 11 цифр, начинается с 7, без плюса и пробелов: `79001234567`. Буквы, плюс и короткий номер — `400`.

Время в ответах — ISO-8601 со смещением, например `2026-10-24T15:00:00+10:00`. Списки идут от новых к старым.

## Экраны

| Экран на схеме | Запросы |
| --- | --- |
| Точка входа | `GET /api/demo-profiles`. Сверху `POST /api/advisor`, снизу регистрация номером. Если токен уже лежит у фронта — `GET /api/cabinet` |
| Вход в кабинет | `POST /api/auth/session`, затем `GET /api/cabinet` |
| Личный кабинет | `GET /api/cabinet` |
| Оборотный кредит и кредит на старт | `GET /api/products/{code}` |
| Ссылка сразу на анкету | форма копится на фронте, на подтверждении один `POST /api/applications` с номером |
| Заполняет анкету, человек уже в кабинете | `POST /api/applications` без номера, статус `draft` |
| Подтверждение номера | `POST /api/applications/{id}/confirm` |
| Свои заявки | `GET /api/applications`, карточка `GET /api/applications/{id}` |
| Свои кредиты | `GET /api/credits`, карточка `GET /api/credits/{id}` |
| Выход | `DELETE /api/auth/session` |

Прямая ссылка со схемы на кредит на старт открывает `GET /api/products/startup`. Ссылка «на получение кредита» открывает анкету продукта из query `product`.

## Авторизация

Один номер — один пользователь. Нового пользователя создать нельзя: и кнопка «Регистрация» на стартовом экране, и номер в чате ищут профиль из `GET /api/demo-profiles`. Повторный вход тем же номером возвращает того же человека и новый токен, а предыдущий токен становится недействительным: запрос с ним даёт `401`. Неизвестный номер даёт `401` и текст «Номер не найден.» Пароля нет.

Токен не нужен.

```json
{"phone": "79001000001"}
```

`200`

```json
{
  "token": "tok_1",
  "user": {
    "id": "user-demo-anna",
    "phone": "79001000001",
    "full_name": "Анна Соколова",
    "role": "Директор",
    "email": "anna.sokolova@severnaya.example",
    "company": {"short_name": "ООО «Северная линия»"}
  }

```

`400` — номер не из 11 цифр или не начинается с 7. `401` — номера нет среди демо-профилей.

### `GET /api/demo-profiles`

Токен не нужен. Список номеров, которыми можно войти.

`200`

```json
  "profiles": [
    {
      "phone": "79001000001",
      "full_name": "Анна Соколова",
      "role": "Директор",

```

Токен обязателен. `204`, тела нет. Этот токен дальше даёт `401`.

### `GET /api/me`

Токен обязателен. В ответе тот же профиль, что в сессии: `id`, `phone`, `full_name`, `role`, `email`, `company`.

`200`


## Продукты

Токен не нужен. Кабинет после входа показывает продукты. Стартовый экран — онбординг: сверху подбор чатом `POST /api/advisor`, снизу регистрация номером. Список продуктов на нём не рисуется.

### `GET /api/products`

`200`

```json
{
  "products": [
    {
      "code": "working_capital",
      "title": "Оборотный кредит",
      "annual_rate_pct": 18,
      "min_amount_rub": 300000,
      "max_amount_rub": 3000000,
      "min_term_months": 3,
      "max_term_months": 24
    }
  ]
}
```

Остальные продукты в том же списке. Условия:

| `code` | Ставка | Сумма, ₽ | Срок, мес. | Ступени лимита |
| --- | --- | --- | --- | --- |
| `working_capital` | 18% | 300 000 – 3 000 000 | 3–24 | 3 000 000, 1 500 000, 800 000, 300 000 |
| `startup` | 24% | 200 000 – 1 000 000 | 6–36 | 1 000 000, 500 000, 200 000 |
| `equipment` | 16% | 500 000 – 5 000 000 | 12–60 | 5 000 000, 2 000 000, 1 000 000, 500 000 |
| `contract` | 19% | 400 000 – 2 000 000 | 3–18 | 2 000 000, 1 000 000, 400 000 |
| `overdraft` | 22% | 100 000 – 1 500 000 | 1–12 | 1 500 000, 500 000, 100 000 |
| `refinance` | 14% | 300 000 – 4 000 000 | 6–60 | 4 000 000, 2 000 000, 800 000, 300 000 |

Дольше 60 месяцев нет ни у одного продукта.

```json
  ]

```

`200` для старта:

```json
{
  "code": "startup",
  "title": "Кредит на старт",
  "annual_rate_pct": 24,
  "min_amount_rub": 200000,
  "max_amount_rub": 1000000,

```

Поля `equipment`, `contract`, `overdraft` и `refinance` приходят в `fields` того же ответа. `404` — неизвестный `code`.

### `POST /api/advisor`

Токен не нужен. Формула ведёт диалог и сама выбирает продукт. Тело:

```json
{"goal": null, "amount_rub": null, "term_months": null, "text": "нужен станок"}
```

`goal` — код продукта или `null`. Сумма, срок и выручка — целые или `null`. `purpose` и `business_plan` — строки или `null`. `phone` — `7` и десять цифр из демо-профилей или `null`. `text` — последняя реплика человека, до 500 знаков. `history` — до шести предыдущих реплик `{role, text}`, `role` равен `user` или `assistant`, текст до 300 знаков. Клиент каждый ход присылает уже собранные ответы: черновик живёт в сессии браузера, пока номер не подтверждён.

`200`

```json
{
  "reply": "Для оборудования сумма от 500 000 до 5 000 000 ₽. Какая сумма нужна?",
  "voice": "qwen",
  "brief": {"say": "ask_amount", "product_title": "Кредит на оборудование", "annual_rate_pct": 16},
  "answers": {"goal": "equipment", "amount_rub": null, "term_months": null},
  "choices": [{"id": "500000", "label": "500 000 ₽"}],
  "product": null,
  "done": false
}
```

Свободный вопрос о продукте не меняет уже собранные ответы. Его смысл ищут по карточкам в `ML/knowledge`: базовая модель кодирует вопрос и фрагменты, в ответ попадают только карточки с общими словами темы. Если вопрос ссылается на уже сказанное («этот кредит», «что ещё», «а срок?»), поиск идёт по последним репликам человека и берёт карточку этого продукта, а не общий список. Модель видит до шести последних реплик и пересказывает карточку, не добавляя чисел. Если пересказ противоречит карточке, в `reply` остаётся фраза из карточки, а `voice` равен `formula`. Если карточки нет, модель своими словами отказывает по этой реплике и недавнему разговору и не отвечает из своих весов; `voice` равен `qwen`. Если отказ выдумывает факт или не подняты модель или поиск, `reply` — «Вопрос не понят. Попробуйте переформулировать.»

`brief` — единственные факты, которые можно сказать в шаге анкеты. `voice` равен `qwen`, если фразу сказала базовая Qwen2.5-1.5B-Instruct без адаптера. Если модель недоступна, добавила число не из `brief`, ответила короче 20 знаков, заменила вопрос другим или подменила номер договором, `voice` равен `formula`: ту же реплику собирает шаблон по полю `say` и словам-триггерам вроде «привет», «станок», «кассовый». `product` появляется, когда сумма и срок уже внутри вилки. Дальше формула спрашивает выручку или план, затем номер демо-профиля и код `0000`. СМС не отправляется: код написан в ответе. Когда код совпал, `done: true`, заявка считается и пишется на этот номер, в ответе есть `token` и `saved`. Прежний токен этого номера становится недействительным. До кода `token` и `saved` равны `null`. `400` — сумма, срок или выручка пришли не целым числом, либо номер не в формате `7` и десять цифр.

## Заявка

Общие поля тела:

| Поле | Тип | Правило |
| --- | --- | --- |
| `product` | один из кодов каталога | обязательно |
| `loan_amount_rub` | целое > 0 | обязательно. Сумма внутри вилки продукта, иначе `400` |
| `loan_term_months` | целое ≥ 1 | обязательно. Срок внутри вилки продукта, иначе `400`. Максимум по каталогу — 60 месяцев |
| `phone` | строка номера или поле опущено | на создании из ссылки обязателен; в кабинете номер берётся из сессии |
| `purpose` | строка | обязательна для оборотного, оборудования, контракта и рефинансирования. Пустая строка — `400` «Укажите цель кредита.» |
| `profitability_rub` | целое, руб/мес, может быть отрицательным | обязательна для оборотного, оборудования, контракта, овердрафта и рефинансирования. Нет поля — `400` «Укажите доходность.» |
| `profitability_confirmed` | bool | обязательно для оборотного |
| `collateral` | bool | обязателен для оборотного. Бэк поле хранит. Лимит от залога не меняется |
| `business_plan` | строка | обязательна и не пустая для старта |
| `own_funds_rub` | целое ≥ 0 или `null` | необязательно |
| `credit_rating` | целое 0–1000 или `null` | необязательно |

Полная заявка в ответах:

```json
{
  "id": "app-1",
  "status": "scored",
  "product": "startup",
  "phone": "79001234567",
  "purpose": "",
  "loan_amount_rub": 1000000,
  "loan_term_months": 12,
  "profitability_rub": null,
  "profitability_confirmed": false,
  "collateral": false,
  "business_plan": "Текст плана.",
  "own_funds_rub": 100000,
  "credit_rating": 500,
  "created_at": "2026-10-24T15:00:00+10:00",
  "pipeline": "ai",
  "fallback": false,
  "monthly_payment_rub": 94560,
  "flow_rub": 160000,
  "limit_rub": 1000000,
  "decision": "approve",
  "credit_id": "credit-1",
  "report": {
    "flow_basis": "explicit",
    "risks": ["client_concentration", "lumpy_revenue"],
    "quote": "Средний поток равен 160000 руб. в месяц."
  }
}
```

До скоринга `pipeline`, `monthly_payment_rub`, `flow_rub`, `limit_rub`, `decision`, `credit_id` и `report` равны `null`, `status` равен `draft`, `fallback` равен `false`.

`monthly_payment_rub` в заявке — аннуитет запрошенной суммы. Его видит скорер. Платёж выданного кредита считается отдельно, от одобренного лимита.

`decision`:

- `approve` — `limit_rub` равен запрошенной сумме
- `reduced` — `limit_rub` больше 0 и меньше суммы
- `reject` — `limit_rub` равен 0
- `unknown` — потока нет, `limit_rub` равен `null`, кредит не открывается

Короткая карточка в списках — полная заявка без `business_plan` и без `report`.

### `POST /api/applications`

Два входа.

В кабинете токен уже есть. Тело без `phone`. Бэк пишет черновик на этого пользователя и скоринг не запускает. `201` и полная заявка со `status: draft`.

Со ссылки токена нет. В теле есть `phone` и вся анкета. Бэк находит пользователя среди демо-профилей. Неизвестный номер — `401` и «Номер не найден.», пользователь не создаётся. Известный номер считает заявку сразу и открывает кредит, если решение `approve` или `reduced`. `201`:

```json
{
  "token": "tok_1",
  "user": {"id": "user-1", "phone": "79001234567"},
  "application": {}
}
```

`application` — полная заявка со `status: scored`. Фронт сохраняет `token` и открывает кабинет.

`400` — не хватает поля продукта или номер кривой. Черновик из кабинета без токена тоже `401`: со ссылки номер в теле обязателен.

### `POST /api/applications/{id}/confirm`

Токен обязателен. Черновик этого пользователя. Тело:

```json
{"phone": "79001234567"}
```

Номер в теле совпадает с номером сессии. Бэк запускает пайплайн один раз. `200` — полная заявка со `status: scored`.

Повторный confirm по уже посчитанной заявке возвращает `200` и тот же результат, второй раз скоринг не идёт.

`400` — номер не совпал с сессией или заявка ещё не заполнена.

### `GET /api/applications`

Токен обязателен. `200`:

```json
{"applications": []}
```

Внутри короткие карточки, включая черновики.

### `GET /api/applications/{id}`

Токен обязателен. `200` — полная заявка, с текстом плана и `report`.

## Кредиты

Кредит появляется вместе со скорингом, когда `decision` равен `approve` или `reduced`. `reject` и `unknown` остаются только заявкой.

`amount_rub` кредита равен `limit_rub`. `monthly_payment_rub` кредита — аннуитет этой суммы на срок заявки по ставке продукта. При `reduced` этот платёж ниже платежа в заявке.

`status` кредита в этом контуре всегда `active`.

### `GET /api/credits`

```json
      "application_id": "app-1",
      "product": "startup",
      "status": "active",

      "monthly_payment_rub": 94560,

```

Токен обязателен. `200` — карточка списка плюс график. В графике `loan_term_months` строк, платёж в каждой строке одинаковый.

## Какой пайплайн считает

Скоринг вызывают два места: `POST /api/applications` со ссылки (в теле есть номер) и `POST /api/applications/{id}/confirm`. Форма ответа одна.

**AI, по умолчанию.**

1. Если продукт `startup` или в заявке есть текст плана, энкодер читает `business_plan` и возвращает поток, основание, риски и цитату. Платёж и покрытие из текста модели выбрасываются.
2. Если плана нет, поток — это `profitability_rub`.
3. Платёж заявки считает аннуитет по ставке продукта: месячная ставка `годовая / 12`, сумма — запрошенная, срок — из заявки, округление половины вверх до рубля. На ставке 20% сумма 800 000 ₽ и срок 12 месяцев дают 74 108 ₽. Живые продукты используют свою ставку из каталога.
4. Скорер лимита получает поток, этот платёж, сумму, срок, свои деньги, рейтинг, флаг подтверждения доходности и риски. Пустые свои деньги и пустой рейтинг приходят в скорер как 0. Флаг расходов всегда ложный. На выходе `0` или ступень лимита этого продукта. Ступень выше запрошенной суммы обрезается до суммы.

**Математика, фолбек.** Включается, если энкодер не вернул JSON, цитаты нет в тексте плана, или скорер не загрузился. В ответе `pipeline` равен `math` и `fallback` равен `true`.

1. Поток берётся из отчёта энкодера, если он успел посчитаться. Иначе из `profitability_rub`. Пока энкодер не подключён, поток из текста плана — наибольшее число от 10 000 до 5 000 000. Текста без такого числа недостаточно: поток пустой, подставного значения нет.
2. Платёж заявки — тот же аннуитет по ставке продукта.
3. Лимит — наибольшая ступень продукта, которая не выше запроса и чей аннуитет не больше потока. Если поток не положительный, лимит `0`. Если потока нет вообще, `decision` равен `unknown`.
4. `report.risks` пустой, `quote` пустая строка, `flow_basis` равен `form`, когда поток взят с формы.

`flow_basis` у энкодера: `explicit`, `inferred` или `unknown`.

Риски фронт подписывает так. Незнакомый код показывает как есть.

| Код | Подпись |
| --- | --- |
| `thin_margin` | тонкая маржа |
| `rent` | аренда |
| `slow_ramp` | медленный выход на поток |
| `client_concentration` | зависимость от одного клиента |
| `lumpy_revenue` | рваная выручка |
| `seasonality` | сезонность |
| `fixed_costs` | постоянные расходы |
| `location` | место |
| `negative_unit_economics` | отрицательная юнит-экономика |
| `subsidies` | зависимость от субсидий |
| `competition` | конкуренция |
| `rare_payment` | редкие платежи |
