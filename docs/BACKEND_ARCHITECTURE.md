# Бэкенд кабинета

Один сервис `backend`. Своя Postgres `credit-db`. Общей схемы с другими сервисами нет.

Redis кэширует публичные `GET /api/products` и `GET /api/products/{code}` на 60 секунд. У каждого продукта в каталоге своя ставка, вилка суммы и срок. Если Redis недоступен, ответы читаются из кода сервиса.

Kafka нет: второго сервиса нет, событие слать некому.

Авторизация — `Authorization: Bearer`, как в `docs/contract.md`. Cookie и отдельный admin JWT в этот контур не входят.

`GET /health` сервиса отвечает `200 {"status":"ok"}`, только если Postgres выполняет `SELECT 1`. Иначе `503 {"status":"error","reason":"db"}`. Пароль и адрес базы в ответ не попадают. На стенде это порт 8000. Origin кабинета на тот же путь отдаёт HTML страницы входа со статусом 200.

При старте пишется одна строка: имя сервиса, окружение, хост базы, состояние Redis. Дальше в лог идут только ошибки и предупреждения. Токен и заголовок Authorization не логируются.

Голос чата — отдельный процесс `qwen` без своей базы. Бэкенд зовёт его по HTTP, потому что реплика нужна в том же ходе. Модель — Qwen2.5-1.5B-Instruct, квант Q4, только CPU. Поиск идёт по карточкам `ML/knowledge`: модель пересказывает найденный фрагмент. Почему голосу хватает 1,5 млрд параметров, написано в `README.md`.

Поднять стенд с моделью: `docker compose up --build` из корня. Сайт — http://localhost:8080, API — http://localhost:8000. Без модели: `docker compose stop qwen`, затем `docker compose -f docker-compose.yml -f docker-compose.no-model.yml up -d --build`. Бэкенд в этом режиме не ждёт `qwen` и говорит шаблоном. Если `/health` перестал отвечать, `scripts/heal-compose-runtime.sh` пересоздаёт контейнер сервиса без удаления томов. Неготовый `qwen` не перезапускает: скрипт трогает его только в состоянии `unhealthy`.
