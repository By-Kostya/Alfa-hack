# Бэкенд кабинета

Один сервис `backend`. Своя Postgres `credit-db`. Общей схемы с другими сервисами нет.

Redis кэширует публичные `GET /api/products` и `GET /api/products/{code}` на 60 секунд. Каталог в этом контуре не меняется, отдельной инвалидации нет. Если Redis недоступен, ответы читаются из кода сервиса.

Kafka нет: второго сервиса нет, событие слать некому.

Авторизация — `Authorization: Bearer`, как в `docs/contract.md`. Cookie и отдельный admin JWT в этот контур не входят.

`GET /health` отвечает `200 {"status":"ok"}`, только если Postgres выполняет `SELECT 1`. Иначе `503 {"status":"error","reason":"db"}`. Пароль и адрес базы в ответ не попадают.

При старте пишется одна строка: имя сервиса, окружение, хост базы, состояние Redis. Дальше в лог идут только ошибки и предупреждения. Токен и заголовок Authorization не логируются.

Поднять стенд: `docker compose up --build` из корня. Если `/health` перестал отвечать, `scripts/heal-compose-runtime.sh` пересоздаёт контейнер сервиса без удаления томов.
